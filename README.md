# 实时悬浮字幕器 · Realtime Caption Bar

一个 Windows 桌面端的实时字幕工具：捕获电脑正在播放的声音（系统声音回环，不占用麦克风），调用火山引擎 / 豆包流式语音识别转成文字，以无边框置顶字幕条压在所有普通窗口上方，同时把完整文字稿保存为 TXT。

面向的实际场景是**看直播课、听线上会议、看无字幕视频**——需要实时跟上语音内容，又不想让字幕窗口被其他应用盖住。

## 解决什么问题

浏览器方案的置顶在 Windows 上并不可靠：切到微信、PDF、播放器之后，网页悬浮窗经常被压在下面，字幕一旦不置顶，工具就失去意义。参考 Buzz 的 presentation window 和 obs-localvocal 的字幕源做法，本项目改为**桌面原生置顶窗口 + Win32 强制置顶兜底**，从窗口层级上保证字幕始终可见。

## 功能特性

- **原生置顶字幕条**：无边框、可拖动、点击其他应用后仍保持在最上层
- **系统声音捕获**：基于 Windows WASAPI 回环录音，只监听所选音频输出设备，不采集麦克风
- **实时语音识别**：接入火山引擎 / 豆包流式 ASR，中间结果快速上屏，最终分句写入文字稿
- **低延迟与自动重连**：音频积压保护、过期结果丢弃、识别落后或长时间无结果时自动重建会话
- **文字稿导出**：按 `名称-YYYYMMDD-HHMMSS.txt` 命名，未保存时关闭会二次确认
- **外观可调**：字号、透明度、置顶开关，窗口位置与配置自动持久化
- **手动测试模式**：不接识别服务也能输入字幕验证置顶效果

## 技术栈

| 层次 | 选型 |
| --- | --- |
| 桌面 GUI | PySide6（优先）/ PyQt6（自动降级） |
| 窗口置顶 | Qt `WindowStaysOnTopHint` + Win32 `SetWindowPos(HWND_TOPMOST)` 兜底 |
| 系统音频 | `soundcard`（WASAPI loopback）+ `numpy` |
| 实时识别 | 火山引擎流式 ASR，`websockets` 长连接 |
| 异步调度 | `asyncio` + `threading`，GUI 与识别线程解耦 |

## 工作原理

```text
系统扬声器 / 耳机播放声音
        │  WASAPI loopback 采集
        ▼
   音频重采样与切片（约 0.8s 滑动缓冲）
        │  WebSocket 流式上行
        ▼
   火山引擎流式 ASR
        │  中间结果 ────────────► 字幕条刷新（最长 20 字，仅显示最新）
        │  最终结果（definite）──► 文字稿累积
        ▼
   TXT 导出（transcripts/名称-日期时间.txt）
```

## 快速开始

环境要求：Windows 10/11、Python 3.10+。

```powershell
git clone https://github.com/4phj4/realtime-caption-bar.git
cd realtime-caption-bar
python -m pip install -r requirements.txt
python native_caption.py
```

如果本机已装 `PyQt6`，无需额外处理；程序优先使用 `PySide6`，缺失时自动尝试 `PyQt6`。

## 配置识别服务

程序通过**环境变量**读取密钥，不把凭据写入代码或配置文件：

```powershell
setx VOLC_ASR_APP_ID "你的APP ID"
setx VOLC_ASR_ACCESS_TOKEN "你的Access Token"
setx VOLC_ASR_RESOURCE_ID "volc.seedasr.sauc.duration"
```

若使用豆包流式语音识别模型 1.0，资源 ID 改为 `volc.bigasr.sauc.duration`。设置后重新打开程序，先点「检测豆包配置」确认读取成功，再点「开始实时字幕」。

不使用识别服务时，也可以在控制面板输入字幕并点「记录这句」做纯界面验证。

## 设置与文字稿

程序在同目录生成 `native_caption_settings.json`，保存字幕条位置、控制面板位置、字号、透明度、置顶开关与音频输出设备。该文件包含本机设备 ID，因人而异，因此不纳入版本控制。

文字稿输出到 `transcripts/`，文件名格式：

```text
名称-YYYYMMDD-HHMMSS.txt
```

文字稿出现新增内容后，控制面板会标记「未保存」；此时关闭程序会先询问「保存文字稿 / 不保存并关闭 / 取消关闭」。取消名称输入时程序不会退出，避免误丢内容。

## 手动验收清单

1. 启动后出现黑色字幕条和控制面板。
2. 在控制面板输入测试字幕，字幕条立即显示，最多显示最新 20 个字。
3. 按回车或点击「记录这句」，当前测试字幕进入文字稿。
4. 点击「保存文字稿」并输入名称，在 `transcripts/` 下生成 `名称-日期时间.txt`。
5. 点击「开始系统声音测试」，播放电脑里的视频或音乐。
6. 验收标准：电脑播放声音时音量条波动；旁边人说话时音量条不应明显波动。
7. 连接蓝牙耳机时，点击「刷新音频设备」，在「音频输出」中选择正在播放直播声音的耳机。
8. 设置豆包环境变量后，点击「检测豆包配置」，再点击「开始实时字幕」。
9. 播放直播课或视频，识别结果出现在字幕条，最终分句进入文字稿。
10. 点击浏览器、微信、PDF、播放器等普通窗口，字幕条仍在这些窗口上方。
11. 拖动字幕条、调整字号 / 透明度后关闭程序，再次打开应自动恢复上次设置。
12. 有新内容未保存时关闭控制面板，应弹出保存提醒。

## 低延迟设计

实时字幕的体验主要取决于「落后多少」，因此做了几处针对性处理：

- **刷新节流**：中间结果每 50 ms 刷新一次且只显示最新结果，服务端集中返回多条时不会依次追播过期字幕。
- **积压保护**：待发送音频最多保留约 0.8 秒，处理跟不上时丢弃最旧音频，优先保证音画同步。
- **首字加速**：开启适度首字加速，开头少量文字可能被后续结果修正，这是实时性与准确率的取舍。
- **自动重连**：识别进度持续落后约 2 秒，或检测到持续声音但 8 秒无新结果时，丢弃旧会话并重连，控制面板显示重连原因。
- **双遍结果分离**：一遍增量结果负责字幕条实时显示，二遍最终结果负责写文字稿，最终分句不阻塞字幕刷新。

## 已知限制

- 仅支持 Windows（依赖 WASAPI 回环与 Win32 `SetWindowPos`）。
- 蓝牙耳机若同时出现 `Stereo / Headphones` 与 `Hands-Free / 通话模式`，需选择前者，后者音质与延迟表现较差。
- 自动重连优先恢复实时性，极端情况下重连点附近尚未形成最终分句的文字可能缺失。
- 目前仅接入火山 / 豆包一家服务商，暂未做多服务商适配与识别参数调优。
